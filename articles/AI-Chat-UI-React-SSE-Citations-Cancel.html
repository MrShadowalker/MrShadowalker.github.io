补刊说明：本文补齐原定学习日；资料与题目于 2026-11-21 检索核验。

后端能返回流，不代表用户得到可靠的对话体验。浏览器可能刷新，网络可能断开，模型也可能在写出半句后失败。今天用 React 和 TypeScript 给最小对话服务做一个前端契约：用户能看到生成进度、授权引用、取消结果和明确的失败状态。

一、先分开“创建任务”和“订阅事件”

沿用第 22 天纵向链路：一轮对话消息创建一个 task_id，前端以任务 ID 订阅事件。用户点击停止时调用任务取消 API，随后继续接收终结事件，不能只在浏览器关闭连接。

浏览器原生 EventSource 适合单向服务端事件，自动重连时会带上 Last-Event-ID；但它的构造参数只有 URL 和凭据模式，没有任意自定义请求头入口。因此这个示例采用同站点会话 Cookie，鉴权由服务端负责；取消接口另做 CSRF 防护。不能把 API Key 或租户 ID 放在 URL 查询串里。WHATWG Server-sent events（检索日期：2026-11-21）

React 官方说明，Effect 的清理会在依赖变化和组件卸载时执行，开发环境 Strict Mode 还会额外跑一次 setup 与 cleanup。因此创建连接与关闭连接必须对称，不要因组件重渲染产生两条订阅。React useEffect（检索日期：2026-11-21）

applyTaskEvent 的核心条件是 event.seq > view.lastSeq，否则忽略重复事件。事件序号出现缺口时不要直接拼接；标记 SYNCING 并获取服务端快照或重新订阅。task_succeeded 到来后再读权威结果与正式引用。重试生成则创建新 task_id，保留旧回答的“失败/不完整”状态，不在同一气泡内悄悄覆盖。

四、引用、取消与无障碍状态

引用只能由服务端返回已授权的 evidence_id，前端用内部文档接口生成链接；不要把模型生成的任意 URL 原样放进 href。流中展示的引用可以先标为“待验证”，只有任务完成且服务端通过证据校验后才显示为正式引用。task_failed 时保留已生成文字，但标注“未完成”，避免用户误当完整答案。

用户点击“停止生成”时，前端先禁用重复点击并展示“正在停止”，发送取消命令；只有收到 task_cancelled 或查询到对应终态才显示“已停止”。关闭 EventSource 只断开浏览器订阅，不能证明上游模型已经停止或停止计费。

用 role="status" 向辅助技术播报“排队中、正在生成、重连中、已完成、已停止”等低频状态。不要把每个 Token 都放进 live region，否则读屏会不断被打断。W3C 对 status 消息的说明支持这种状态提示方式。W3C ARIA status 技术（检索日期：2026-11-21）

今天动手的验收

用本地 Fake SSE 服务制造四个场景：先发 1、2 再断线并重放 2、3；第 3 条引用无权限；用户在第 4 条点击停止；服务端在已输出文本后发失败。验收时检查：无重复文本、无越权链接、取消前不宣称已停止、失败有可见标记、键盘可操作且状态可被读屏感知。页面截图只能证明界面出现，事件日志与断线重放记录才证明协议正确。

五、今日面试题

以下题面来自公开牛客面经与社区题库，检索日期均为 2026-11-21。企业归属只按发帖者自述，未获企业官方核验；社区题库不应冒充大厂原题。参考答案是本文的工程归纳。

1. 为何选择基于 Fetch 的 SSE，而不是原生 EventSource 或 WebSocket？

  • 方向 / 难度：前端流式协议选型，中级。
  • 参考答案：仅需服务端推送且能用同站点 Cookie 鉴权时，原生 EventSource 的重连与事件 ID 更省实现；需要自定义请求头、POST 请求体或更细的中止控制时可用 Fetch 流，但必须自己正确解析 SSE 帧并处理重连；频繁双向通信才考虑 WebSocket。本篇的创建任务与订阅分离，所以采用 EventSource。
  • 追问：若企业只接受 Bearer Header，能否把 Token 放入 EventSource URL？不应在 URL 暴露长期令牌；考虑受控 Fetch 流或服务端签发短期、限任务的流凭证，并评估日志泄露。
  • 来源：牛客“百度前端一面二面”用户自述，正文直接提问基于 Fetch 的 SSE 与原生 SSE、WebSocket 取舍；企业归属未经官方确认。

2. 模型流把 Markdown 代码块截在半路，页面怎样渲染？

  • 方向 / 难度：AI 对话渲染，中级。
  • 参考答案：流式草稿允许不完整语法，可先显示纯文本或使用容忍未闭合块的增量渲染器，按小时间窗口合并更新；终态后再解析和净化完整 Markdown。代码块、引用链接不能直接拼进 innerHTML。
  • 追问：每个 Token 都重新解析整篇 Markdown，长会话卡顿怎么办？分块缓存已稳定部分、节流渲染并对历史消息做虚拟列表或分页。
  • 来源：牛客“得物 AI 应用开发二面”用户自述，正文直接提问未闭合 Markdown 与长聊天滚动；企业归属未经官方确认。

3. 用户点击“停止生成”，怎样避免后端继续耗费模型资源？

  • 方向 / 难度：取消语义，较难。
  • 参考答案：取消是任务命令，服务端标记 CANCEL_REQUESTED 并尝试取消上游请求、清理连接和配额；以终态事件确认结果，已产生的 usage 仍入账。浏览器关闭 SSE 不是取消命令。
  • 追问：供应商不支持取消或在取消前已完成，前端怎么表示？展示实际终态与已产生成本，不伪称“零消耗已停止”。
  • 来源：牛客《80 道 Agent 开发面试题》流式输出题单，公开转发页可直接核对题面；社区整理，非可核验企业原题。
